# Модель данных CropItAll

## DataStore Preferences

### Ключи

| Ключ | Тип | Описание |
| :--- | :--- | :--- |
| `source_folder_uri` | String | URI исходной папки (SAF) |
| `source_folder_path` | String | Читаемый путь для отображения |
| `base_name` | String | Название вебинара (например, «Вебинар_1») |
| `file_prefix` | String | Префикс имени файла (может быть пустым) |
| `crop_rect` | String | Координаты рамки: `left,top,right,bottom` |
| `delete_sources` | Boolean | true = удалять исходники, false = в Корзину |
| `last_operation_summary` | String | Строка последней операции |
| `total_saved_freed` | Long | Сэкономлено удалением (в байтах) |
| `total_saved_pending` | Long | Сэкономлено, но ждёт очистки Корзины (в байтах) |
| `first_launch` | Boolean | true, если программа запущена впервые |
| `training_completed` | Boolean | true, если обучение пройдено |

## Структура папок на устройстве

DCIM/Screenshots/                    ← P_SRC (исходная папка)
├── screenshot_001.png               ← исходные скрины
├── screenshot_002.png
├── screenshot_003.png
├── Вебинар_1/                       ← результаты обрезки
│   ├── 001.jpg
│   ├── 002.jpg
│   └── 003.jpg
├── Вебинар_2/
│   ├── Вебинар_2_001.jpg
│   └── Вебинар_2_002.jpg
└── Корзина/                         ← исходники, ожидающие проверки
├── screenshot_004.png
└── screenshot_005.png


## Формат имени файла

- **Без префикса:** `001.jpg`, `002.jpg`, `003.jpg`
- **С префиксом:** `Вебинар_1_001.jpg`, `Вебинар_1_002.jpg`
- Нумерация: три цифры, начинается с 001.
- Если в папке уже есть файлы — спрашивать пользователя (продолжить нумерацию или изменить имя).
- Нестандартные имена в папке результатов **игнорируются** (нумерация идёт только по шаблону `^\d{3}\.jpg$`).

## Сканирование SAF

- **Только корень** `P_SRC`. Подпапки игнорируются.
- Поддерживаемые форматы: `.jpg`, `.jpeg`, `.png`.
- Фильтрация: **комбинация** MIME-типа (`image/*`) **и** расширения.
- Сортировка: по возрастанию даты изменения (старые первыми) — **на уровне провайдера**.
- Способ: `DocumentsContract.buildChildDocumentsUriUsingTree()` + `ContentResolver.query()`.
- Cursor закрывается через `.use { }`.

## Расчёт экономии

- `Экономия = размер исходника − размер обрезанного файла`
- Учитывается **только после успешного** удаления или перемещения исходника.
- Если операция не удалась — экономия не учитывается.
- Два счётчика:
    - `total_saved_freed` — реально освобождено.
    - `total_saved_pending` — ждёт очистки Корзины.
- Размеры файлов — через `ContentResolver.query()` с `COLUMN_SIZE`.

## Формат строки журнала

Если последний режим — «Удалить»:
12.09.2026 14:30 — Вебинар_1: обрезано 20, пропущено 3, сэкономлено 70 МБ.


Если последний режим — «Переместить в Корзину»:
12.09.2026 14:30 — Вебинар_1: обрезано 20, пропущено 3, сэкономлено 70 МБ (после очистки Корзины).


Общий отчёт с двумя счётчиками:
Всего сэкономлено: 170 МБ (из них 100 МБ — после очистки Корзины).


При очистке Корзины:
total_saved_freed += total_saved_pending
total_saved_pending = 0


## Журнал ошибок удаления

- Список имён файлов, которые не удалось удалить.
- Формат: `имя_файла (причина)`.
- Показывается в отчёте после завершения.

## Журнал повреждённых файлов

- Список имён файлов, которые не удалось прочитать (`BitmapFactory` вернул `null`).
- Формат: `имя_файла (повреждён или недоступен)`.
- Показывается в отчёте.
- Исходник **не удаляется** и **не перемещается**.
