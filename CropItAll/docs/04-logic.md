# Бизнес-логика CropItAll

## Выбор исходной папки
1. Пользователь нажимает «Выбрать папку».
2. Открывается `ACTION_OPEN_DOCUMENT_TREE`.
3. Выбранный URI сохраняется в DataStore.
4. Запрашивается постоянное разрешение: `takePersistableUriPermission`.
5. При повторном запуске URI восстанавливается, проверяется доступ.
6. Если доступ потерян — URI удаляется, пользователь уведомляется.

## Режим обучения
- Показывается **только при первом запуске** (`first_launch = true`).
- Переключение шагов управляется внутри `MainViewModel`:
    - Шаг 1: `folderUri == null`
    - Шаг 2: `folderUri != null && baseName.isEmpty()`
    - Шаг 3: `folderUri != null && baseName.isNotEmpty()`
- После завершения — `training_completed = true`.
- Повторно не включается.

## Проверка «Папка не пуста»
- Происходит **на главном экране**, после ввода названия вебинара.
- Проверяет: существует ли `P_SRC/<baseName>/` и есть ли в ней файлы.
- Если папка не пуста — диалог:
    - «Добавить файлы к существующим (с продолжением нумерации)» — продолжить.
    - «Выбрать другую папку» — вернуться к вводу имени.

## Сканирование файлов
- Сканируется **только корень** `P_SRC`.
- Подпапки игнорируются.
- Поддерживаемые форматы: `.jpg`, `.jpeg`, `.png`.
- Сортировка: по возрастанию даты изменения (старые первыми).
- Если папка пуста — диалог до входа в CropActivity:
    - «В папке нет изображений. Выбрать другую папку?» (Да/Отмена).
- Список файлов передаётся в `CropActivity` через `FileRepository` (интерфейс + реализация, без DI).

## Обрезка одного файла
1. Пользователь выделяет рамку (в координатах View).
2. Нажимает «Crop it».
3. Координаты рамки преобразуются в координаты Bitmap (внутри CropOverlayView).
4. Загружается **полноразмерный** Bitmap из URI.
5. Если `BitmapFactory` вернул `null`:
    - Записать в журнал ошибок (имя, причина).
    - Пропустить файл.
    - **Не удалять** исходник, **не создавать** обрезанный.
6. Если рамка полностью на полях — изображение не обрезается, переход к следующему.
7. Иначе — обрезка по пересечению рамки и изображения.
8. Сжатие в JPEG, качество 90.
9. Сохранение в `P_SRC/<Вебинар_N>/` с именем `001.jpg` (или `Вебинар_N_001.jpg`).
10. Исходник: удаляется или перемещается в Корзину (по настройке).
11. Экономия учитывается **только после успешного** удаления/перемещения.
12. Освобождение памяти (`bitmap.recycle()`).
13. Переход к следующему изображению.

## Обрезка всех файлов (Crop it ALL)
1. Пользователь нажимает «Crop it ALL».
2. Диалог: «Обрезать все N файлов с текущей областью?» (Да/Нет).
3. Если «Да» — обрабатываются файлы **от текущего до конца списка**.
4. Пропущенные ранее (до текущего) — не трогаются.
5. Во время обработки — overlay с `ProgressBar` и текстом «Обработка X из Y».
6. Кнопка «Отмена» — прерывает процесс. Текущий файл обрабатывается до конца, затем стоп.
7. После завершения — возврат на главный экран с отчётом.

## Смена вебинара (внутри CropActivity)

1. Пользователь нажимает «ГОТОВО» (или системный «Назад»).
2. Диалог 1: «Вебинар: <имя>. Выйти из обрезки или сменить вебинар?»
  - **«Выйти»** → закрыть CropActivity, вернуться на главный экран.
  - **«Сменить вебинар»** → диалог 2.
  - **«Отмена»** → продолжить обрезку.
3. Диалог 2: «Новый вебинар»
  - Поле ввода с текущим именем (автофокус, курсор в конце).
  - **«Отмена»** → ничего не менять.
  - **«Начать»** → если имя не пустое:
    - `settingsRepository.saveBaseName(newName)`.
    - Обновить `currentWebinarName` в CropActivity/CropViewModel.
    - Текущий слайд — первый в новой папке.
    - Все последующие обрезки идут в `<P_SRC>/<newName>/`.
  - Если имя пустое → Toast «Введите название вебинара», диалог не закрывать.

**Причина:** в одной исходной папке может быть несколько вебинаров.
Пользователь обрабатывает первый, доходит до слайда из второго,
вводит новое имя — и продолжает, не выходя на главный экран.

## Пропуск слайда
- Нажатие `>` без «Crop it» = пропуск.
- Файл остаётся в `P_SRC` нетронутым.
- Кнопки «Crop it» и «Crop it ALL» скрыты, если рамка не выделена.

## Перемещение исходников в Корзину
- **Гибрид:** сначала `DocumentsContract.moveDocument()`.
- Если провайдер не поддерживает (`UnsupportedOperationException`) — копирование + удаление.
- Если удаление не удалось — записать в журнал (имя + причина), продолжить.

## Удаление исходников
- Через `DocumentsContract.deleteDocument(uri)`.
- Если `false` или исключение — записать в журнал (имя + причина), продолжить.
- Экономия не учитывается для неудалённых файлов.

## Корзина
- Программа знает о папке `Корзина/`.
- При запуске: если в Корзине есть файлы — диалог «В Корзине N файлов. Удалить их?».
- При очистке: `total_saved_freed += total_saved_pending`, `total_saved_pending = 0`.
- Переобрезка: пользователь вручную перемещает файл из Корзины в `P_SRC`.

## Обработка ошибок
- Все операции чтения/записи/удаления — в `try-catch`.
- Ошибки выводятся через `Toast` или в поле И2.
- Приложение не должно аварийно завершаться при:
    - Отсутствии файлов.
    - Потере доступа.
    - Ошибках ввода-вывода.
    - Повреждённых файлах.
    - Неудачном удалении.

## Жизненный цикл
- Процесс массовой обрезки продолжается в фоне, пока жив `CropViewModel`.
- Если система убивает Activity — процесс прерывается.
- При возврате: показать, что процесс был прерван, предложить продолжить с текущего файла.

## Преобразование координат
- Выполняется **внутри** `CropOverlayView`.
- `CropOverlayView` узнаёт размеры Bitmap через `setBitmapSize(w, h)`.
- Отдаёт результат через `OnCropRectChangedListener`:
    - `viewRect` — для рисования.
    - `bitmapRect` — для обрезки.
- Формула fitCenter:
  scale = min(viewWidth / bitmapWidth, viewHeight / bitmapHeight)
  offsetX = (viewWidth − bitmapWidth × scale) / 2
  offsetY = (viewHeight − bitmapHeight × scale) / 2

- Пока изображение грузится (`bitmapWidth == 0`):
    - Рамка рисуется на весь View.
    - Касания игнорируются.

## Рамка
- Минимальный размер: 70×70 dp.
- Хватательные зоны: адаптивные, 10% от размера рамки, min 24 dp, max 40 dp.
- Углы и стороны не перекрываются.
- Приоритет захвата: углы → стороны → центр.
- Предотвращение переворота: координаты не пересекаются, остановка на minSize.
- Не выходит за границы View.
- **Не сбрасывается** при смене изображения.
- Восстанавливается из DataStore при входе в CropActivity.
- При отсутствии в DataStore — охватывает весь View.
